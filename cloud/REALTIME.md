# Realtime deployment

The hosted Site is now a Vinext/Cloudflare Worker application. `public/bankbook/` contains the existing vanilla UI. `/` requires the platform's ChatGPT identity and redirects to `/bankbook/index.html`. The existing owner-only audience is preserved.

## Storage and identity

- Logical D1 binding: `DB`. The hosting platform provisions it from `.openai/hosting.json`.
- `bankbook_documents`: one latest revision per authenticated Site user ID.
- `bankbook_document_chunks`: UTF-16-safe pieces of the serialized document, with each row below D1's 2 MB row limit. Writes and the revision pointer are in one D1 batch. Reads of the pointer and its chunks are also one batch.
- SQL migrations are generated by Drizzle and schema-only. No user data or test fixtures are seeded in production.
- Identity comes from the dispatch-owned authenticated headers through `getChatGPTUser()`. The payload cannot select another user's records. Writes also require the same Origin and the expected signed-in user ID.
- No database credential or site bypass token is included in client code or this repository.

## Protocol

- `GET /api/state`: identity, revision, and the caller's document. `?revision=N` can return unchanged metadata without the large document.
- `PUT /api/state`: `{ userId, revision, mutationId, document }`. A compare-and-swap guards the previous revision. A conflict returns 409 and the current data. The latest mutation ID is idempotent.
- `GET /api/events`: authenticated Server-Sent Events. It checks the caller's revision every 1.2 seconds while connected, rolls the stream every 25 seconds, and requests a 500 ms reconnect delay. The client checks every 4 seconds as a fallback and again when the page becomes visible.

The client writes a draft to localStorage first. Its acknowledged baseline is kept in IndexedDB to avoid storing cover-image strings twice in the localStorage quota. Pending changes survive a reload and retry on reconnection. Independent changes merge by record ID and field, including nested game entries. Same-field and delete-vs-edit conflicts require a user choice. A form in progress is not replaced by a remote update. Existing local data on a device with no cloud metadata requires a migration choice when cloud records already exist.

The document request is limited to 6,000,000 UTF-8 bytes. The UI can still hit the browser's device-local storage quota first and reports a save error rather than dropping a draft silently. Streams and background timers can be suspended by mobile operating systems; opening or focusing the page fetches the latest revision.

## Development

Requires Node 22.13+ (tested using the bundled Node 24 runtime). Install using the Sites helper and locked dependencies. Generate and build:

```sh
npm run db:generate
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_familiar_imperial_guard.sql
npm run dev -- --port 5173 --hostname 127.0.0.1
```

Loopback preview uses the starter's mock sign-in at `/signin-with-chatgpt?return_to=/bankbook/index.html`. Preview databases and auth cookies are separate from production. The mock sign-in is absent from production.

```sh
node --test test.mjs sync.test.mjs
npx tsc --noEmit
```

For publication, use the native Sites save/deploy flow for the existing Site and preserve its audience. Never create runtime tables from request handlers. Never use preview identity headers as production credentials.

## GitHub Pages

GitHub Pages can serve the static client, but cannot run the authenticated API or D1 database. Its status bar links to the hosted Site for realtime use. The backend source is included under `cloud/` in the GitHub repository. If moving the backend to a different host, deploy authenticated storage there before enabling writes from a new frontend origin; do not make the existing private API public to work around authentication.
